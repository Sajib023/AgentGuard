# RannaIQ — Single Master Prompt (Zero to Launch rule)

> **How to use:** paste this ONE prompt into Cursor agent mode / Kiro / Claude Code inside an empty repo. Afterwards, interact ONLY with the allowed triggers: "Click to approve", "Click to continue", "Click to proceed", "Yes/Continue", "Deploy". All 8 mandated modules are covered below in order.

---

You are a senior full-stack AI architect and autonomous build agent. Generate the complete, production-grade system for **RannaIQ** — a RAG-based AI copilot for restaurant managers that analyzes customer review sentiment and seasonal trends to recommend precise ingredient purchase quantities. Execute the 8 modules below strictly in order. After each module, pause and wait for an approval trigger ("Click to continue"). Never skip a module. Generate all code, docs, configs, and seed data yourself; do not ask open-ended questions, only present approval checkpoints.

**Module 1 — Core Product & AI Instructions.** Build a Next.js (TypeScript, Tailwind, Recharts) dashboard + FastAPI (Python) backend. Target users: owner-managers of mid-size Dhaka Bangladesh restaurants (demo persona "Tuhin Bhai", 2-branch chain). Features: (a) voice/text chat panel — OpenAI Whisper STT (`whisper-1`) for questions, OpenAI TTS (`tts-1`) reads recommendations aloud; (b) Sentiment Radar — aggregated complaint/praise facets with citations to source reviews; (c) Demand vs Stock chart with 14-day forecast; (d) Recommendation cards with precise quantities (kg/L units) and confidence; (e) one-click Approve Purchase Order. User journey: login → voice question "what should I order for Friday?" → agent reasons over RAG + MCP tools → quantity recommendation with rationale → TTS playback → approve PO → email via n8n. Persist conversation history with full citations.

**Module 2 — Data Architecture.** PostgreSQL schema: `restaurants, branches, dishes, ingredients, recipes(dish_ingredient joints), inventory_movements, purchase_orders, suppliers, price_history, reviews, review_chunks(pgvector embeddings + contextual_prefix), sentiment_facets, kg_edges(subject,relation,object,weight), seasonal_index(dish,week,multiplier), users, roles, audit_log, token_ledger`. Knowledge graph tables model ingredient↔dish↔supplier↔season edges. Seed script generates 14 days of synthetic POS sales with Eid + monsoon distortion, 600 synthetic Banglish/English reviews, and a demo supplier price feed. Pipelines: review ingestion (dedupe→PII redact→language detect→sentiment facets→semantic chunking→contextual prefixes→pgvector), and nightly seasonal-index recompute via Airflow.

**Module 3 — Admin Module.** Role-based access: owner (all), manager (branches assigned), staff (view-only). Admin screens: user CRUD with invite flow, branch management, settings (stock thresholds, TTS voice choice, notification channels, forecast sensitivity), analytics dashboard (API cost from `token_ledger`, forecast accuracy MAPE, top complaint facets, PO approval rate).

**Module 4 — Security Module.** JWT auth with refresh rotation; bcrypt password hashing; RBAC middleware; rate limiting via SlowAPI (per-user and per-endpoint); AES-256 at rest for supplier price data; TLS everywhere; PII redaction pipeline (regex + Presidio-style scans of names/phones inserted deliberately into seeded reviews); prompt-injection filter on all review-derived text (wrap with delimiters + canary tokens + output schema validation); severity-labeled security.md with the vulnerability checklist checked.

**Module 5 — Documentation Module.** Write README.md (one-command setup: `docker compose up --build && python scripts/seed.py`), docs/ARCHITECTURE.md (the module map + request sequence diagrams), docs/API.md (OpenAPI auto-export), docs/DATA_PIPELINE.md (the 5-stage data lifecycle: sources→parse→clean/enrich→store→deliver, naming exact tools), docs/EVALS.md, docs/MCP.md, docs/ADR.md (contextual-RAG etc. decision log).

**Module 6 — Audit Reporting.** Every agent run writes `audit_log` (inputs hash, tools called with args, retrieval ids + scores, outputs, latency, model, tokens). `token_ledger` tracks per-request/per-user OpenAI + local usage and USD cost; add a /audit export endpoint (JSONL) and a monthly compliance summary job. Envelope all LLM calls with a `TracedLLM` wrapper for Langfuse export.

**Module 7 — Presentation & Pitch Deck.** Generate docs/PITCH.md as a 10-slide deck: Problem (Dhaka restaurants lose 12–18% margin to over/under ordering), Solution (voice copilot → kg-precision POs), Demo script, Market (BD food service TAM, 1.2M establishments), Wedge (Banglish/monsoon/Eid signals competitors ignore), Business model (BDT 4,500/mo SaaS per branch + per-PO overage), GTM (supplier partnerships), Moat (proprietary review KG), Team, Roadmap. Also generate a 150s video script with shot list and narration.

**Module 8 — Deployment Requirements.** Produce docker-compose.yml (api, db+pgvector, minio, ollama, langfuse), Dockerfile per service, .env.template with key names only, GitHub Actions CI (lint, test, docker build), Vercel config for the frontend, Render deployment notes for API+DB, and a `deploy/tunnel/cloudflared.yml` + `deploy/tunnel/ngrok.sh` exposing the local Ollama node as an SSE MCP endpoint. Include `scripts/check_env.py` validating env and printing a readiness report.

**Technical rules.** Three custom MCP servers (stdio + SSE transports): `inventory-mcp` (list stock, usage velocity, on-hand), `review-mcp` (faceted review search over pgvector, facet rollups), `forecast-mcp` (seasonal index, sales velocity, recommended-quantity computation, GraphRAG multi-hop Explainer). Integrate three external MCP servers: official postgres MCP (read-only role), fetch MCP (Open-Meteo), filesystem MCP (PO/PDF export). Use LangGraph for orchestration and the OpenAI Agents SDK as MCP client. Local Ollama models on distinct subtasks: Qwen2.5-7B (seasonal summary), Llama 3.1-8B (sentiment fallback), DeepSeek-R1-8B (forecast reasoning chain), GLM-4-9B (aspect extraction). Cloud LLMs: GPT-4o (synthesis), GPT-4o-mini (classification/embedding context, with prompt caching); OpenAI text-embedding-3-small for vectors; ColBERT-style reranker for top-50→top-10. Token optimization: semantic cache in pgvector for repeated questions, context pruning (>30-day reviews summarized), model routing by task tier. n8n workflows: (1) daily review ingestion with dedupe alert, (2) PO approval → email/WhatsApp dispatch, (3) weekly PDF report. Evaluation suite in docs/EVALS.md: sentiment F1 on 200 labeled reviews, retrieval hit@10/nDCG using 60 QA pairs, forecast MAPE, and an LLM-as-judge (GPT-4o with a fixed rubric prompt + dual CrewAI review agents) scoring 50 recommendations against human-written baselines; print a scorecard table on run. Ship unit tests for every MCP tool and the forecast math. After Module 8, print a final manifest of all generated files and wait for "Deploy".
